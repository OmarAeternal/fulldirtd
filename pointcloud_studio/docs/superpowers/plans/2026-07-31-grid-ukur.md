# Grid Referensi + Alat Ukur — Rencana Implementasi

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grid referensi yang bisa digeser & diputar bebas sebagai acuan pengukuran, ditambah alat ukur karet dengan angka hidup, ukur sudut, hasil yang menetap, dan ekspor CSV.

**Architecture:** Dua modul baru di atas fondasi Spec 1. `grid.js` memegang satu `THREE.Group` berisi garis-garis di bidang XY lokal; transformnya digerakkan `TransformControls` (gizmo) dan kotak isian numerik yang saling menulis lewat flag anti-lingkaran. `measure.js` ditulis ulang: pointerdown/pointerup dengan ambang 4 px (bukan `click`, yang juga menyala setelah orbit), garis pratinjau yang mengikuti kursor, dan daftar hasil yang menetap dengan label sprite berukuran layar tetap.

**Tech Stack:** Three.js r160 + TransformControls (vendored) · modul ES tanpa bundler · tanpa perubahan backend.

**Spec:** `docs/superpowers/specs/2026-07-31-grid-ukur-design.md`

## Global Constraints

- Bahasa kode, komentar, dan teks UI: **Indonesia**.
- **Tidak ada perubahan backend.** Pytest yang ada harus tetap 44 lulus tanpa disentuh — itu sendiri buktinya.
- Tidak ada dependensi Python baru. Satu berkas JS di-vendor: `frontend/vendor/TransformControls.js` (sudah ada di repo sejak commit spec).
- Grid dan hasil ukur **tidak** menerima `clippingPlanes` — mengiris ketinggian Z tidak boleh memotongnya.
- Arah impor tetap searah: `ui.js → grid.js/measure.js → layers.js → viewer.js`, `hud.js` daun. `measure.js` boleh mengimpor `grid.js`; sebaliknya tidak.
- Verifikasi lewat Chrome headless + CDP (`scratchpad/cdp.py`), bukan klik manual.

- [ ] **Step 2: `ambangRaycast` di `layers.js`**

```js
/** Ambang raycast titik, ikut skala data: 0,05 m tetap terlalu besar untuk
 *  ruangan kecil dan terlalu kecil untuk gedung. */
export function ambangRaycast() {
  const b = boundsGabungan();
  return b ? Math.max(0.02, diag(b) * 0.004) : 0.05;
}
```

Impor `diag` dari `viewer.js`.

- [ ] **Step 2: Tulis `grid.js`**

Grid dibangun di bidang XY lokal, berpusat di titik asal grup — orientasi identitas =
mendatar, cocok dengan data LiDAR Z-up. Jumlah garis dibatasi 400 per sumbu; lewat itu
`ukuran` dipangkas dan panel memberi catatan.

Rotasi disimpan sebagai quaternion; kotak isian adalah Euler urutan `'ZXY'` supaya
"Putar Z" selalu berarti berputar terhadap Z **dunia**. Penulisan kotak isian dari gizmo
dipagari flag `_menulisUI` supaya tidak jadi lingkaran umpan balik yang membulatkan sudut
sedikit demi sedikit.

Perpotongan sinar dihitung analitis (`Ray.intersectPlane` + batas kotak lokal), bukan
raycast ke mesh — lebih tepat dan tidak bergantung pada visibilitas objek.

- [ ] **Step 3: Verifikasi CDP**

- [ ] **Step 1: Tulis ulang `measure.js`**

Titik kunci:
- `pointerdown`/`pointerup` dengan ambang 4 px — `click` juga menyala setelah orbit
- klik diabaikan bila `grid.sedangDiseret()`
- `pointermove` memperbarui garis pratinjau + label hidup saat `sedang.length > 0`
- label sprite `sizeAttenuation:false`, `depthTest:false`; skalanya dihitung ulang tiap
  frame lewat `viewer.onFrame` karena rumusnya beda antara kamera perspektif dan ortho
- sudut dihitung `atan2(|u×v|, u·v)`, bukan `acos(u·v)` — `acos` kehilangan presisi di
  dekat 0° dan 180°
- Esc membatalkan pengukuran berjalan
